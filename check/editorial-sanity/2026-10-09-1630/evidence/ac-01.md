# Evidência AC-01

**Critério**: A home e a rota `/artigos/[slug]` obtêm artigos exclusivamente a partir do Sanity, sem dual-source ativo.

## Prova

`lib/services/posts.ts:79-82`:

```typescript
if (isSanityActive()) {
  return getSanityPublishedPosts(limit);
}
```

`lib/services/posts.ts:112-119`:

```typescript
if (isSanityActive()) {
  const publicPost = await getSanityPostBySlug(slug, { isPreview: false });
  if (publicPost) return publicPost;
  const isPreview = await isPreviewSession(supabase);
  if (!isPreview) return null;
  return getSanityPostBySlug(slug, { isPreview });
}
```

Quando `isSanityActive()` retorna true, o Supabase não é consultado para posts. A tabela `posts` do Supabase permanece apenas como backup histórico.

## Teste

`__tests__/unit/lib/services/posts.test.ts:259-282` confirma que `getPublishedPosts` e `getPostBySlug` delegam para o Sanity quando configurado.

## Resultado

PASS
