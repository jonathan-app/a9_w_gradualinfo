# Evidência AC-06

**Critério**: Respostas públicas e de preview mantêm `Cache-Control: no-store` (e `private, no-store` no preview). Slugs inexistentes respondem 404 real; indisponibilidade de infraestrutura responde status de erro adequado (503/500) sem mascarar falha como 404.

## Problema

`lib/preview/auth.ts:173-186`:

```typescript
export async function isArticleAccessible(
  supabase: SupabaseClient,
  slug: string,
  isPreview: boolean,
): Promise<boolean> {
  // Transição editorial da spec 0006: Sanity como fonte primária única
  if (env.sanity?.projectId && env.sanity?.dataset) {
    try {
      const post = await getSanityPostBySlug(slug, { isPreview });
      return Boolean(post);
    } catch {
      // Erros de infraestrutura transitória não devem gerar falso 404; deixa fluir para a página
      return true;
    }
  }
```

Quando o Sanity está indisponível, `getSanityPostBySlug` lança erro. O `catch` retorna `true`, permitindo o acesso. O middleware (`lib/supabase/middleware.ts:108`) recebe `true` e permite a renderização. O artigo tenta renderizar, mas como o Sanity está fora, o conteúdo não carrega. O Next.js pode responder 200 com página de erro interna, ou o artigo renderiza vazio.

Isso contradiz o AC-06: indisponibilidade de infraestrutura deve responder 503/500, não 200.

## Correção necessária

`isArticleAccessible` deve distinguir "artigo não existe" de "infraestrutura indisponível". Erro de infraestrutura deve lançar exceção (como `PreviewStoreUnavailableError`), não retornar `true`.

## Teste

`__tests__/unit/preview-auth-accessible.test.ts:90-104` confirma que erro de infraestrutura retorna `true` (comportamento atual, incorreto para o AC-06).
