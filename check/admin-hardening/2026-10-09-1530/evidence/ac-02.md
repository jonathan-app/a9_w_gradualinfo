# Evidência AC-02

**Critério**: POST de matrícula valida Origin quando presente; somente se Origin faltar admite Referer canônico. Origin inválido não pode ser compensado por Referer válido, e ausência de ambos é rejeitada. UUID ausente, inválido ou divergente bloqueia antes de enroll. Uma sessão AAL1 autorizada pode matricular seu primeiro TOTP, mas não acessar operações administrativas.

## Prova

Testes:

- `rejeita ausência de origem, Host forjado, null e URL malformada` em `__tests__/unit/admin-hardening.test.ts:188-210`
- `recusa UUID divergente antes da matrícula` em `__tests__/unit/admin-mfa-enrollment.test.ts:112-116`

```typescript
it('rejeita ausência de origem, Host forjado, null e URL malformada', () => {
  expect(
    validateAdminRequestOrigin(
      new Request('https://gradualinfo.com.br/api/admin/auth/login'),
    ),
  ).toBe(false);
  for (const origin of ['null', 'bad-url', 'https://attacker.invalid']) {
    expect(
      validateAdminRequestOrigin(
        new Request('https://attacker.invalid/api/admin/auth/login', {
          headers: { origin, referer: 'https://gradualinfo.com.br/' },
        }),
      ),
    ).toBe(false);
  }
});
```

## Implementação

`validateAdminRequestOrigin` em `lib/admin/auth.ts:128-170`:

- Valida Origin primeiro (linha 154-156)
- Se Origin ausente, valida Referer (linha 159-163)
- Origin inválido não é compensado por Referer válido (linha 156: `return isAllowedOrigin(origin, reqUrl)`)
- Ausência de ambos retorna `false` (linha 169)

UUID validado com `UUID_PATTERN` em `app/api/admin/auth/mfa/enroll/route.ts:31`.

AAL1 pode matricular (enroll), mas `checkAdminUser` em `lib/admin/auth.ts:267-316` exige AAL2 para operações administrativas.

## Resultado

PASS - Origin/Referer validados corretamente, UUID verificado antes de enroll, AAL1 não acessa operações administrativas.
