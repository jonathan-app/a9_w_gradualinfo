# MCP (Model Context Protocol) no boilerplate

> O que é: servidores que dão ao agente (Claude Code, Cursor, Codex, etc.)
> ferramentas reais — dirigir o browser, ler o dev server do Next, buscar
> URLs. Sem MCP, o agente só lê arquivos e escreve código; com MCP, ele pode
> testar a app rodando de verdade.

## Separação importante

### MCP de engenharia (P0/P1)

- **Playwright MCP**: automação e E2E quando necessário.
- **Next DevTools MCP**: inspeção local do App Router.
- **Supabase MCP**: uso restrito a ambiente de desenvolvimento.
- **Fetch MCP**: requisições HTTP externas quando necessário.

### MCP do produto (futuro)

- **GradualInfo MCP**: só quando capacidades como `search_articles`, `get_article`, `find_sources` existirem.

## O que o boilerplate traz

- `.agents/mcp.json` é o catálogo genérico: Playwright, Next DevTools, Fetch e
  Supabase local. `.vscode/mcp.json` é o adaptador do VS Code e declara apenas
  Playwright e Next DevTools. Um arquivo não ativa os servidores do outro.
- Playwright e Next DevTools usam `npx` com versões exatas. Fetch usa `uvx`
  com versão exata. Nenhum deles entra nas dependências da aplicação.
- O Supabase CLI já expõe MCP em `http://127.0.0.1:54321/mcp` quando a stack
  local está rodando. A configuração rastreada só aceita esse endpoint local.
- `node scripts/check-mcp-config.mjs` confere a configuração. O comando não
  comprova que o servidor iniciou. `/check verify` registra cliente, versão
  efetiva, descoberta e chamada real da ferramenta, resposta e hash da prova.

## Servidores recomendados

| Servidor                  | Para que serve                              | Quando ativar          |
| ------------------------- | ------------------------------------------- | ---------------------- |
| `@playwright/mcp@0.0.83`  | Agente navega e inspeciona a app no browser | Verificar UI           |
| `next-devtools-mcp@0.4.0` | Rotas e erros do Next dev server            | Debugar build/rotas    |
| Supabase CLI local        | Operações no ambiente de desenvolvimento    | Quando necessário      |
| `mcp-server-fetch==0.6.3` | Ler docs e URLs públicas                    | Consultar documentação |

## Segurança

- MCP servers rodam com as permissões do seu usuário: só ative servidores de
  fonte confiável e confira a versão exata configurada antes de iniciar.
- Nunca coloque segredos no `mcp.json`; o Supabase MCP local não exige uma
  credencial de produção nesse arquivo.
- O `fetch` server lê URLs públicas; não use para endpoints com credenciais.

### Supabase MCP: restrição obrigatória

O servidor MCP da stack local do Supabase fica no endpoint de loopback. Use
apenas em desenvolvimento:

```
agente → MCP Supabase → ambiente de desenvolvimento
```

Nunca:

```
agente → produção → database
```

## O que NÃO trazer do repositório de origem

O `scripts/mcp-rag-server.mjs` de origem é específico do motor de conhecimento
(RAG) daquele produto — um boilerplate não nasce com busca semântica sobre o
conteúdo de um site. Se precisar, crie o servidor no produto, não aqui.
